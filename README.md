# PhotoCrew

Share photos with your group. No cloud. No hassle. Everyone shares small thumbnails into one grid, and each person pulls only the full-resolution originals they pick, directly from the owner's phone. There are no uploads, no accounts and no backend.

## Run it

```bash
npm install
npm run dev
```

Vite prints two URLs:

```
➜  Local:   https://localhost:5173/
➜  Network: https://192.168.1.23:5173/   ← open THIS on every phone
```

1. On each phone (all on the same Wi-Fi), open the **Network** `https://` URL. The dev certificate is self-signed, so accept the warning once per device: on iOS tap *Show Details → visit this website*, on Android tap *Advanced → Proceed*.
2. Phone A taps **Create Room**, then **QR**. Phone B scans the QR code or types the 4-character code.
3. Add photos, pick photos, download.

> HTTPS is required. WebRTC signaling crypto, the Screen Wake Lock API and the Web Share API only work in secure contexts. `@vitejs/plugin-basic-ssl` provides the certificate.

Production build: `npm run build`, then serve `dist/` from any static HTTPS host (Netlify, Vercel, GitHub Pages and so on). There is nothing server-side.

## Pages and hosting

The landing page is at `/` (`index.html`, `src/landing/`) and the app is at `/app/` (`app/index.html`). Old `/?room=CODE` links redirect to the app.

Every push to `main` publishes to GitHub Pages (`.github/workflows/deploy.yml`). In the repository, set **Settings → Pages → Source** to **GitHub Actions** once.

To host it elsewhere, run `npm run build` and upload everything in `dist/` to any static HTTPS host. Asset paths are relative, so a sub-folder works too. For link previews, build with your address:

```bash
SITE_URL=https://your-domain.example npm run build
```

Put your contact details in `src/site.ts` before publishing. The demo film is `public/media/photocrew-demo.mp4`, and the app screenshots are in `src/landing/img/`. Its photos come from Unsplash, via Picsum, and are credited in the page footer.

## How it works

| Concern | Implementation |
| --- | --- |
| Matchmaking / signaling | [`trystero`](https://github.com/dmotz/trystero) over public Nostr relays (room id = `room-<CODE>`) |
| Data transport | A **dedicated negotiated `RTCDataChannel`** (id 42) on each Trystero peer connection, which gives full control of chunking and backpressure |
| Thumbnails | `createImageBitmap` (EXIF-aware), then an offscreen canvas, then 300px-wide WebP (falls back to JPEG on Safari), about 15–25KB |
| Full files | Owner reads `File.slice()` lazily and sends **64KB chunks**, pausing when `bufferedAmount > 1MB` and resuming on `bufferedamountlow` (threshold 256KB) |
| Lightbox | On-demand ~1600px preview generated by the owner; it jumps ahead of queued full-res transfers |
| Saving | 1 photo → `<a download>` (plus a "Save to Photos" share action). Multiple → **Save to Camera Roll** (`navigator.share({ files })`) or **Download as ZIP** (JSZip, STORE mode) |
| Link quality | `getStats()` reads the selected candidate pair. host↔host (or host↔private prflx) shows **Local Wi-Fi Direct • Ultra Fast** |
| Wake lock | `navigator.wakeLock` held while in a room, re-acquired when the tab becomes visible again |
| Disconnects | Peer leaves → their photos stay in the grid as *Offline (owner disconnected)*, and pending transfers from them fail gracefully |

### Wire protocol (over the PhotoCrew channel)

- **Control** messages are JSON strings: `hello`, `photo-meta`, `photo-remove`, `request {kind: 'preview' | 'full', photoIds}`, `cancel`, `stream-start`, `stream-abort`, `request-error`.
- **Binary** frames are laid out as `[u32 headerLen][{"s":streamId,"i":chunkIndex}][payload ≤ 64KB]`.
- Both sides create the negotiated channel independently, so `hello` is retried until acknowledged. This guarantees neither side sends photos before the other is listening.

## Tips and limits

- **Keep the owner's tab open and in the foreground.** Mobile browsers suspend WebRTC in background tabs. The wake lock stops auto-lock, but switching apps still pauses transfers.
- **Share sheet batches:** iOS and Android handle about 20 images per share reliably. For bigger batches use ZIP.
- **Memory:** received originals are held in memory until saved. Pulling hundreds of large photos at once on an older phone can exhaust memory, so batches of around 50 are comfortable.
- **HEIC:** iOS converts HEIC to JPEG when you pick photos in Safari. Chrome or Firefox on desktop can't decode HEIC, so those files are skipped with a notice.
- **Different networks:** it still works over the internet via STUN (badge shows *P2P via Internet*). Mobile data, guest/office Wi-Fi and other strict (symmetric) NATs need a TURN relay, otherwise you'll see *could not connect to peer … after exchanging SDP*. Set repository secrets `TURN_URLS` (comma-separated `turn:`/`turns:` URLs), `TURN_USERNAME` and `TURN_CREDENTIAL` and the deploy workflow bakes them in; locally, put the same values in `.env.local` as `VITE_TURN_URLS`, `VITE_TURN_USERNAME`, `VITE_TURN_CREDENTIAL`. They are visible in the public bundle, so use a provider account with a usage cap. Relayed connections show *Relayed connection* on the badge.
- **Matchmaking** depends on public Nostr relays. If friends don't appear within about 15 seconds, have everyone reload. PhotoCrew uses 8 relays to stay resilient when some are down.
